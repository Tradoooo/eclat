Le projet

« WAMR apporte le bac à sable ; Éclat apporte la frontière de capacités. Chaque accès du module devient un message synchrone vers un courtier — un autre processus — qui décide, seul, selon une politique déclarative à refus par défaut. »

Trois couches d'isolation indépendantes

  • Bac à sable WebAssembly — mémoire linéaire bornée, pas d'appel système direct.
  • Processus QNX sans abilities — le courtier tourne dans un processus dont on retire les abilities.
  • Politique de sécurité noyau — exprimable par capacité, pas seulement par processus.

Quatre mécanismes, tous mesurés

  • Politique déclarative à refus par défaut (TOML) — plages d'identifiants et de valeurs par capacité.
  • Budget CPU avec mise à mort du processus enfant (fork + pipe + poll + SIGKILL, portables sur QNX).
  • Vérification d'empreinte avant chargement : un seul octet modifié refuse le module.
  • Journal d'audit à hachage enchaîné, avec vérificateur indépendant.

Niveau d'honnêteté

  • Les chiffres de gigue de la boucle 1 kHz sont dominés par l'émulateur, pas par le module : sous QEMU il n'y a ni vrai timer ni isolation vCPU (p50 ≈ centaines de µs à 1 ms, p99 en dizaines de ms).
  • Ce qui est prouvé : la boucle reste vivante et garde son compte de tics (3000 tics, 2999 mesures de gigue, dans chacune des 3 phases) pendant la mise à mort d'un module ennemi.
  • Ce qui n'est pas prouvé : la performance temps réel — elle exige une cible matérielle physique. L'artefact brut le dit lui-même.
  • Aucune affirmation de certification : Éclat fournit isolation et politique, pas une qualification.
  • La publication de /dev/cap a échoué (retour -1) : le courtier retombe sur le nom « cap ». Le chemin complet resmgr_attach/iofunc reste le chantier de finition.

Submission — Devpost dossier (English)

Éclat

A third-party WebAssembly module runs on a safety-critical QNX controller: it can do nothing beyond what the policy allows, and the real-time control loop keeps running while it does.

The gap. WebAssembly is not ported to QNX: ~150 entries read in the official qnx-ports index, zero wasm/wamr/wasi; qnx-ports/wamr → 404; search org:qnx-ports wasm → 0 repositories. Almost everything else is already there (rust, lua, grpc, ros2, tensorflow, …).

The contribution. Éclat turns every outbound access of a module into a synchronous message to a resource manager that decides — on one side only, in a process without abilities. It is not the porting (that exists, PR #5200, not ours): it is the layer above it.

The twin. The Python twin earned its keep: it caught a real bug — the -1 sentinel meaning "no id constraint" silently collided with the legitimate id -1. The C engine answered CAP_OK where the twin answered CAP_DENIED_RANGE. Without a second implementation, that bug would have shipped.
